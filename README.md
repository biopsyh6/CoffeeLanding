## Отчет

Первоначально разобрался с ИИ со структурой проекта, так как на nextjs не часто пишу. Узнал про zod для задания правил формы. Опирался на первочанальную структуру, которую предложил ИИ в LeadForm. В дальнейшем изменял всё сам. Также приходилось править цвета элементов, шрифтов, так как Gemini выбрал неудачные варианты. Также и с местоположением элементов (карточки товаров с изображениями, форма, навигационная панель, текст основной). 
Сразу, для проверки спама, использовал Map, а заявки пока не хранил. Потом уже решил подключить базу данных через Supabase (PostgreSQL). Там хранятся заявки, в которые входят поля с временем отправки на рассмотрение. 
page.tsx сразу взял с Gemini, потом тоже переделывал. Брал в основном структуру, далее редактировал под себя. 
Также использовал ИИ для исправления ошибок в работе сайта. 
Сразу Gemini предложил в качестве бд использовать Prisma и Vercel Postgres, для деплоя - Vercel, но были трудности с регистрацией на сайте. Было решено использовать Supabase для бд, а для деплоя - Netlify. А первоначально было предложение просто присылать заявку через бота в тг, без бд. Но я решил, что правильнее будет всё-таки хранить где-то заявки. Но от бота не отказался. В итоге заявка дублируется через бота. На localhost работает хорошо. После деплоя приходили сообщения в тг с задержкой. Далее и вовсе перестали приходить. Не понял в чем проблема, не хватало времени дебажить. Оставил как есть.
Телеграм бота сделал сам по гайдам. 
Форму, внешний вид сайта, карточки, навигационную панель делал сам, параллельно рассматривая варианты ИИ.
Также для Supabase Gemini предложил подключать всё через Prisma. Для меня легче было использование нативного клиента @supabase/supabase-js. Не использовал SQLite, так как ИИ написал, что проект будет развернут в Serverless-окружении. В таких средах локальная файловая система эфемерна (read-only).
Также реализовал работу с umt.
Превью ссылки в месенджерах сделал, но почему-то не отображается корректно.
